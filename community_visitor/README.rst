社區訪客管理：升級與時區相容性
================================

18.0.1.3.2 升級注意事項
----------------------

* 新建預約會固定建立者的時區；住戶 Portal 的日期與每日時段使用表單顯示的
  住戶時區，日期轉為 UTC 儲存。
* ``schedule_tz`` 為選填。18.0.1.3.0 遷移將升級當下既有預約的此欄設為空值，
  不推測住戶、建立者或社區所在地時區，也不平移原有起訖日期。
* 舊週期授權未設定時區時，依原有順序採用「核驗人員 user.tz → context tz → UTC」。
  因此同一筆舊授權在不同核驗人員時區下，仍維持原本可能不同的判定結果。
* 後台會顯示「舊授權尚未固定時區，暫依核驗人員時區，請管理者確認後設定」。
  管理者確認既有授權原意後才固定時區；系統不強制台北或要求住戶猜測。
* 曾套用未發布的舊實驗遷移之隔離 DB，應由原始備份重建並重設升級起始版本，
  再驗證完整遷移；不要批次清除已由管理者明確設定的新授權時區。

驗證
----

完整模組使用 ``--test-tags /community_visitor``；本次流程回歸使用
``--test-tags community_visitor_flow``，涵蓋 legacy 核驗人員時區優先序、
context／UTC fallback、新建時區固定、Portal 確認、郵件渲染及證件借還。
並行同碼核驗及同證領用需以兩個實際 HTTP 連線另行驗證。
